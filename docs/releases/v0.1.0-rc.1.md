# Restrict Language v0.1.0-rc.1

Restrict Language v0.1.0-rc.1 is the first release candidate for the
synchronous WebAssembly Component boundary. It keeps the v0.0.1 scalar Core
Wasm compatibility profile and adds an explicit, versioned Component path.

## Component interoperability

- Generate normalized WIT, Canonical ABI adapters, validated Component Wasm,
  and stable interface/content metadata from checked `ComponentInterfaceIr`.
- Lift and lower `String`, `List`, fixed-length-validated `Array`, records,
  `Option`, `Result`, and user enums/variants recursively.
- Expose affine resources through `own`, call-scoped `borrow`, and exactly-once
  drop semantics.
- Represent value-capturing closures as once-callable resources and expose
  generic functions only through explicit concrete instances.
- Validate packaging, composition, compatibility classification, resource
  lifecycle, and runtime execution.

## Independent Rust conformance

The release gate exercises both interoperability directions:

- a Rust-produced Component called by a Restrict consumer; and
- a Restrict-produced Component called by a Rust consumer.

The two sides share only the versioned WIT world and Canonical ABI. They do not
share an allocator, linear memory, arena layout, or internal representation.

## Warder project model

Warder uses one authored `warder.toml` and one generated `warder.lock` at the
repository root. Direct local source packages do not carry leaf manifests or
leaf lock files. `warder build --component` publishes the validated
`.component.wasm`, normalized `.component.wit`, and `.component.toml` metadata
as one transactional artifact set.

## Deliberate boundaries

- Component publication is explicit: source visibility alone does not expose
  a declaration through the Component ABI.
- Rich external-WIT guest imports and scalar external implementation/export
  conformance are included. Rich external implementation exports and
  external-WIT resources still fail closed.
- Resource factories and methods are scalar-signature in this candidate.
  Resource/callable-bearing captures, `many` callables, and generic nominal
  boundary types remain follow-on work.
- Full WASI 0.2 command, network, and HTTP profiles are separate host-profile
  work.
- Async functions, futures, streams, cancellation, backpressure, and cleanup
  across suspension are reserved for v0.2.0.

## Verify from source

The reviewed `core-wasm-v0.1.0-rc.1.json` baseline records the intentional
deterministic artifact and memory changes in the collection workload. The
v0.0.1 baseline remains available as historical evidence.

```bash
mise run ci
```

This is a prerelease candidate, not the stable v0.1.0 release.
