Compiler notes

Type inference without widening the promise

v0.0.1 preview · Updated August 4, 2026 · 7 min read

Inference is useful when it removes repetition from ordinary code. It is dangerous when it quietly implies that every inferred type has a stable representation outside the language. Restrict v0.0.1 separates those two concerns.

Inference starts from both directions

The compiler combines constraints discovered from an expression with the type expected by its surrounding context. That lets generic calls, function values, lambda parameters, and empty local containers get useful types without forcing annotations onto every intermediate value. 

fun identity: <T>(value: T) -> T = {
    value
}

fun answer: () -> Int32 = {
    42 |> identity
}

The call is still OSV: the value comes first and the generic function is the verb. The expected Int32 result and the literal agree on the same substitution for T.

Ownership remains part of the answer

Type inference does not bypass affine checking. Heap-backed values move when consumed, while copyable scalar values may be read again. Resolving a type and validating how often its value is used are different stages, but both have to succeed before code generation.

The host boundary is intentionally smaller

Generic functions, records, lists, Option, and Result can participate in computations inside Restrict. A public WebAssembly export must currently resolve to concrete scalar parameters and results. This is why a generic helper can feed a scalar wrapper, but the helper itself cannot be exported. 

fun add_one: (value: Int32) -> Int32 = {
    value + 1
}

export fun public_answer: () -> Int32 = {
    41 |> add_one
}

This boundary keeps the preview honest. It avoids freezing record layouts, string ownership, or generic calling conventions before those decisions have a complete design and runtime story.

What comes after the preview

At the v0.0.1 tag, user-defined ADTs, source-level forms and associated types, temporal affine types, and direct composite host values remained design work. The current compiler has since added closed enums and a method-only, statically dispatched form slice. Associated types, generic forms or adoptions, default methods, dynamic dispatch, TAT, and the composite host ABI remain deliberately deferred.
