# Restrict Language v0.1.0

Restrict Language v0.1.0 is the first stable release of the synchronous
WebAssembly Component boundary. It promotes the B1 contract validated in
v0.1.0-rc.1 and includes the completed language, Warder, language-server, and
editor work committed after that candidate.

## Synchronous Component interoperability

- Generate normalized WIT, Canonical ABI adapters, validated Component Wasm,
  and stable interface/content metadata from checked `ComponentInterfaceIr`.
- Lift and lower `String`, `List`, fixed-length-validated `Array`, records,
  `Option`, `Result`, and user enums/variants recursively.
- Expose affine resources through `own`, call-scoped `borrow`, and exactly-once
  drop semantics.
- Represent value-capturing closures as once-callable resources and expose
  generic functions only through explicit concrete instances.
- Validate packaging, composition, compatibility classification, resource
  lifecycle, and pinned-runtime execution.
- Exercise independent Rust-produced Component to Restrict consumer and
  Restrict-produced Component to Rust consumer calls through WIT and the
  Canonical ABI without sharing allocators or internal layouts.

## Language and diagnostics

- Compose completed blocks, matches, and values left-associatively through
  direct OSV calls, pipes, and anonymous scopes.
- Keep newlines as whitespace and use `;` when a following identifier could be
  parsed as another verb in the same maximal OSV expression.
- Report parse stops and non-callable verbs with source lines, Unicode-correct
  columns, carets, and actionable guidance.

## Warder workflows

- Use one authored root `warder.toml` and one generated root `warder.lock`,
  with no dependency leaf manifests.
- Treat an explicit root `[component]` selection as the default `warder build`
  artifact; `--component` asserts it and `--core` requests Core Wasm.
- Rebuild on root manifest, root source, and direct local-dependency source
  changes with `warder build --watch`.
- Compile public synchronous zero-argument Boolean test functions and execute
  each one in a fresh Wasm instance with captured output and trap reporting.

## Language server and VS Code extension

- Add scoped and type-directed completion, cross-file definitions and
  references, semantic highlighting, reference CodeLens, inlay hints, and
  LSP-backed compiler commands.
- Bundle the VS Code client, retain safe CLI fallback, add reproducible VSIX
  packaging, and verify the native server through a real JSON-RPC smoke test.
- Version the extension source as 0.1.0. Marketplace publication remains a
  separate distribution step and is not performed by this GitHub release.

## Deliberate boundaries

- The ordinary Core Wasm compatibility profile remains scalar-only; rich
  interoperability uses the explicit Component path.
- Rich external-WIT guest imports and scalar external implementation/export
  conformance are included. Rich external exports and external-WIT resources
  still fail closed.
- Full WASI 0.2 command, network, and HTTP profiles remain separate host work.
- Async functions, futures, streams, cancellation, backpressure, and cleanup
  across suspension remain the v0.2.0 scope.

## Verify from source

artifacts and memory behavior. Earlier RC and v0.0.1 baselines remain as
historical evidence.
